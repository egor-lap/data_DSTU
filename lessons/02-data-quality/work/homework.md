## H1 Правила функции

`clean_export(source)` принимает исходную таблицу и возвращает `clean`, `quarantine`, `audit`.

`clean` — подготовленный слой: одинаковые повторные доставки исключены как `replays`, `county_code` очищен через `str.strip()`, числовые поля (`source_row`, `action_taken`, `loan_amount`, `income`) приведены к числам, `income` может оставаться `NaN`. В `clean` только строки, где известен `source_row`, `action_taken` in {1, 2, 3}, `loan_amount` известна и > 0, `county_code` после `strip()` = `"11001"`.
- `quarantine` — исходные значения строк, не прошедших правила, плюс `reason` (`некорректный source_row`, `некорректный action_taken`, `некорректная сумма кредита`, `некорректная территория`, `некорректный доход`). Повторы сюда не идут. При конфликте версий одного `source_row` функция падает через `assert`.
`audit` — журнал `input`, `replays`, `clean`, `quarantine`, `parse_errors`. Баланс: `input == replays + clean + quarantine`.

## H3 Проверка года и виды проблем

В копии `wrong_year` у первой строки `activity_year` изменён на `"2022"`. Проверка `eq("2023").fillna(False).all()` вернула `False` — нарушение обнаружено. `fillna(False)` считает неизвестный результат непрохождением правила и не меняет исходный столбец. `export` при этом сохранён.

Три вида проблем:

1. Исходный пропуск — `source_row = 99`, `income` пустой. Реакция: строка остаётся в `clean`, `income = NaN`, ноль не подставляется.
2. Ошибка преобразования — `source_row = 2` (`loan_amount = "oops"`), `source_row = 5` (`income = "BAD"`). Реакция: строки уходят в `quarantine` с причинами `некорректная сумма кредита` / `некорректный доход`, `parse_errors` растёт.
3. Необычно большая сумма — `source_row = 326`, `loan_amount = 57005000.0`. Это валидное число, правило его не отбрасывает; сумма выводится отдельно (`loan_amount > 5_000_000`) для смыслового просмотра.
